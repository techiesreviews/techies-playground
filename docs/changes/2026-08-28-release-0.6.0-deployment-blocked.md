# Release 0.6.0 deployment blocked by missing token

- Date: 2026-08-28
- Owner: Codex deployment verification
- Status: complete
- Disposition: inconclusive
- Related version: 0.6.0
- Related commit/issue: `86b454a`; GitHub Actions run `33185403268`; follows `2026-08-28-release-0.6.0.md`

## Context

Release commit `86b454a` reached `origin/main`, but the production workflow was initially skipped because repository variable `CLOUDFLARE_DEPLOY_ENABLED` was `false`. The user explicitly requested live publication, so the gate was temporarily enabled and the same run was retried through GitHub Actions. This record preserves the deployment outcome separately from the successful pre-push release record.

## Hypothesis and success criteria

If the deployment gate was the only blocker, rerunning the verified commit with the gate enabled would execute tests/build, publish through the pinned Cloudflare action, and make the 0.6.0 bundle observable at `https://play.techies.tools`.

## Options considered

- Run Wrangler directly from the workstation. Rejected because repository policy requires normal deployments to use the GitHub pipeline unless a direct deployment is explicitly requested.
- Leave the gate enabled after the failed run. Rejected because future pushes would repeatedly attempt a deployment without credentials.
- Restore the gate and document the missing secret. Selected because it preserves the repository's safety control and identifies the exact external prerequisite.

## Implementation or prototype

The gate was changed from `false` to `true`, run `33185403268` was retried, and the gate was restored to `false` after the Cloudflare step failed. No direct Cloudflare command was run. Current-state architecture documentation now names the required repository variables and Actions secret.

## Result

The source release is complete on `main`, but production publication is not complete. The pipeline cannot authenticate to Cloudflare until a repository Actions secret named `CLOUDFLARE_API_TOKEN` is created. The live domain still serves the older bundle.

## Disposition and rationale

Inconclusive for deployment. Application tests and build passed in GitHub Actions, but the publish stage was never authorized, so no production verdict can be made for 0.6.0.

## Documentation impact

Updated `docs/architecture.md`, `docs/product-history.md`, and the change-record index. The existing 0.6.0 changelog and package version remain correct for the source release.

## Follow-ups and open questions

- Create repository Actions secret `CLOUDFLARE_API_TOKEN` with a Cloudflare token authorized for the configured Workers account.
- Temporarily enable `CLOUDFLARE_DEPLOY_ENABLED`, rerun the production workflow, verify the live bundle, then restore the gate if automatic deployments should remain paused.
