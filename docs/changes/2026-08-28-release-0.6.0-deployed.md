# Release 0.6.0 deployed successfully

- Date: 2026-08-28
- Owner: Codex deployment verification
- Status: complete
- Disposition: kept
- Related version: 0.6.0
- Related commit/issue: GitHub Actions run `33205835385`; supersedes `2026-08-28-release-0.6.0-deployment-blocked.md`

## Context

The first 0.6.0 production run passed tests/build but could not authenticate to Cloudflare because `CLOUDFLARE_API_TOKEN` was absent. The user added the missing repository Actions secret and requested continuation of the same deployment workflow.

## Hypothesis and success criteria

With the token configured, a workflow dispatch from current `main` should pass every job, publish to Cloudflare, and cause the live domain to reference a bundle containing the 0.6.0 release title and final feature code. The temporary deployment gate must return to `false` afterward.

## Options considered

- Rerun the older release commit. This would publish the application but omit the deployment-diagnosis documentation now on `main`.
- Dispatch the workflow from current `main`. Selected because it deploys the exact current source and uses the intended GitHub pipeline.
- Run Wrangler directly. Rejected because direct deployment was not requested and repository policy prefers the pipeline.

## Implementation or prototype

The repository secret name was confirmed without reading its value. `CLOUDFLARE_DEPLOY_ENABLED` was temporarily set to `true`, `deploy.yml` was dispatched from `main` at `db639cb`, and run `33205835385` was watched through completion. After success, the gate was restored to `false`. The live HTML and referenced hashed JavaScript were then fetched with cache-busting parameters.

Release 0.6.0 is live on `play.techies.tools`. The GitHub pipeline and independent live-bundle inspection both confirm publication of the intended build.

## Disposition and rationale

Kept. Adding the missing repository secret resolved the only external blocker; no application or workflow code change was needed.
