- Date: 2026-11-07
- Owner: fleet-lead
- Status: in-progress
- Disposition: kept
- Related version: unreleased

## Context

The deploy and WordPress sync workflows pinned Node 22 while local work and the agent kit already use Node 24. The project wants one Node version everywhere. `package.json` has no `engines` field, and there is no `.nvmrc`.

## Hypothesis and success criteria

Tests and the production build pass under Node 24 with no other change. Success is a green deploy run after the release.

## Options considered

- Keep Node 22 in CI: leaves two Node versions in use.
- Move CI to Node 24: chosen.

## Implementation or prototype

`node-version` changed from 22 to 24 in `.github/workflows/deploy.yml` and `.github/workflows/sync-wordpress-release.yml`. The sentence in `docs/testing.md` that said CI uses Node 22 now says Node 24. No action versions changed. `kit init` also added the "Review loop" pointer line to `AGENTS.md`.

## Tests and evidence

| Environment | Procedure/command | Expected | Actual | Evidence |
| --- | --- | --- | --- | --- |
| Local Linux, Node 24.22.2 | `npm ci && npm test` | All tests pass | 63 passed, 0 failed | Executed Node TAP summary |
| Local Linux, Node 24.22.2 | `npm run build` | Vite build succeeds | Built in about 2.9 s; existing large-chunk warning | Executed command output |
| Local Linux, Node 24.22.2 | `npx wrangler deploy --dry-run` | Worker bundle validates | Passed; bindings listed, exited at `--dry-run` | Executed command output |

## Result

Everything passed under Node 24. The earlier Windows stall on 24.15.0 did not appear on 24.22.2.

## Disposition and rationale

Kept. The check run after release shows the real workflow result (see the release record or the deploy run).

## Documentation impact

`docs/testing.md` line about the CI Node version, this record, and `docs/changes/README.md`.
